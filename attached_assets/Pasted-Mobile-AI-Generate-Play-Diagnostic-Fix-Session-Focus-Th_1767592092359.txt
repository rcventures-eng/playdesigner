Step 4: Verify Response Structure
The mobile canvas expects a specific data structure. Verify the API returns:
typescriptinterface GeneratedPlay {
  players: Array<{
    id: string;
    label: string;      // "QB", "RB", "X", "Y", "Z"
    x: number;          // Canvas coordinate
    y: number;          // Canvas coordinate
    color: string;      // Hex color
    side: 'offense' | 'defense';
  }>;
  routes: Array<{
    id: string;
    playerId: string;   // Links to player.id
    points: Array<{ x: number; y: number }>;
    style: 'straight' | 'curved';
    routeType: 'pass' | 'run' | 'block';
    isPrimary?: boolean;
    isMotion?: boolean;
  }>;
  formation?: string;   // e.g., "Spread", "Trips Right"
}
If the structure doesn't match, mobile won't render correctly.
Common Failure Points
Failure Point A: Mobile Not Sending Required Fields
Desktop might send additional fields mobile doesn't:
typescript// Desktop might send:
{
  prompt: "...",
  format: "5v5",
  type: "offense",
  existingPlayers: [...],  // Mobile might be missing this
  gameFormat: "flag",       // Mobile might be missing this
}
Fix: Ensure mobile sends ALL required fields.
Failure Point B: Response Coordinate Mismatch
Desktop uses logical coordinates (694x392 canvas). If mobile uses different canvas dimensions without scaling, players/routes appear wrong or off-screen.
Fix: Mobile must either:

Use same logical coordinate system and scale for display
Transform coordinates from API response to mobile canvas size

Failure Point C: Route Parsing Failure
If Gemini returns routes in an unexpected format, parsing fails silently:
typescript// Expected:
routes: [{ playerId: "1", points: [{x: 100, y: 200}, ...] }]

// Gemini might return:
routes: [{ player: "QB", path: "slant" }]  // Different structure!
Fix: Make parsing more robust, handle multiple formats.
Failure Point D: CORS or Credentials Issue
Mobile might not be sending credentials:
typescript// WRONG:
fetch('/api/generate-play', { method: 'POST', body: ... })

// RIGHT:
fetch('/api/generate-play', { 
  method: 'POST', 
  credentials: 'include',  // Required for session auth
  headers: { 'Content-Type': 'application/json' },
  body: ... 
})
The Fix
Once you've diagnosed the issue, implement the fix. The goal is:

Mobile uses the exact same endpoint as desktop (/api/generate-play)
Mobile sends the exact same request body structure as desktop
Mobile parses the response the exact same way as desktop
If 60-80% of the play is correct, that's acceptable — coaches can fine-tune

If there are two separate implementations, consolidate to one. Create a shared function/hook that both desktop and mobile use:
typescript// shared/useGeneratePlay.ts or lib/generatePlay.ts
export const generatePlay = async (params: {
  prompt: string;
  format: string;
  type: 'offense' | 'defense';
}): Promise<GeneratedPlay> => {
  const response = await fetch('/api/generate-play', {
    method: 'POST',
    credentials: 'include',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(params),
  });
  
  if (!response.ok) {
    const error = await response.json();
    throw new Error(error.message || 'Generation failed');
  }
  
  return response.json();
};
Then both desktop and mobile import and use this same function.
