## Feature Overview

Build a mobile/tablet-optimized experience for the Play Designer using a 3-step wizard workflow. This is a **separate mobile experience**, not a responsive redesign of the desktop version.

**Core Principles:**
1. Landscape-first — require horizontal orientation for the canvas
2. Canvas-first — get users to the field immediately, defer configuration
3. AI-forward — make AI generation the easy path on mobile
4. Session persistence — never lose a user's work, even if they haven't signed up yet


## Critical Technical Requirements

### Session Persistence (IMPORTANT)

The play must NEVER be lost if the user needs to create an account or log in.

**Implementation:**
```typescript
// On any play state change, persist to sessionStorage
useEffect(() => {
  if (playState.players.length > 0 || playState.routes.length > 0) {
    sessionStorage.setItem('rc_draft_play', JSON.stringify({
      players: playState.players,
      routes: playState.routes,
      shapes: playState.shapes,
      playNotes: playState.playNotes,
      format: selectedFormat,
      name: playName,
      tags: selectedTags,
      timestamp: Date.now()
    }));
  }
}, [playState, selectedFormat, playName, selectedTags]);

// On component mount, restore from sessionStorage
useEffect(() => {
  const draft = sessionStorage.getItem('rc_draft_play');
  if (draft) {
    const parsed = JSON.parse(draft);
    // Check if draft is less than 24 hours old
    if (Date.now() - parsed.timestamp < 24 * 60 * 60 * 1000) {
      // Restore state
      setPlayState({ players: parsed.players, routes: parsed.routes, ... });
      setSelectedFormat(parsed.format);
      // ...
    }
  }
}, []);

// After successful save or account creation, clear draft
const clearDraft = () => sessionStorage.removeItem('rc_draft_play');
```

### Post-Authentication Flow

When user creates account or logs in from Step 3:
1. Auth modal closes
2. User is now authenticated
3. Step 3 UI updates to show authenticated options
4. Play state is preserved (from sessionStorage)
5. User can now tap "Save to My Plays"

### Mobile Touch Handling

For drag-and-drop on touch devices:
```typescript
// Use pointer events for unified mouse/touch handling
onPointerDown={handlePointerDown}
onPointerMove={handlePointerMove}
onPointerUp={handlePointerUp}

// Prevent scroll while dragging
const handlePointerDown = (e: PointerEvent) => {
  e.preventDefault();
  (e.target as HTMLElement).setPointerCapture(e.pointerId);
  // ... drag logic
};
```

### Route Drawing on Mobile

Long-press to initiate route drawing:
```typescript
const LONG_PRESS_DURATION = 500; // ms

const handlePointerDown = (e: PointerEvent, playerId: string) => {
  longPressTimer.current = setTimeout(() => {
    // Open route menu for this player
    setActivePlayerForRoute(playerId);
    setShowRouteMenu(true);
  }, LONG_PRESS_DURATION);
};

const handlePointerUp = () => {
  clearTimeout(longPressTimer.current);
};
```

## Routing Setup

Create a new page at `client/src/pages/mobile-designer.tsx` that will be accessible at `/mobile`.

**In `mobile-designer.tsx`:**
```tsx
import { MobilePlayDesigner } from '../components/mobile/MobilePlayDesigner';

const MobileDesignerPage = () => {
  return <MobilePlayDesigner />;
};

export default MobileDesignerPage;
```

**Add route to router (typically in `App.tsx`):**

Find where routes are defined (likely using Wouter) and add ONE new route entry:
```tsx
<Route path="/mobile" component={MobileDesignerPage} />
```

Do NOT modify any existing routes. Just add this single new one.

**Result:**
- `rc-football.com/` → Desktop experience (unchanged)
- `rc-football.com/mobile` → New mobile wizard experience
