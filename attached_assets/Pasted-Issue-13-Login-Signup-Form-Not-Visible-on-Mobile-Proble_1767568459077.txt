Issue 14: Route Colors Must Match Player Colors
Problem: Routes are currently drawn in a single color (red). On desktop, routes match the color of the player they belong to.
Fix Required:

Route line color should match the player's color:

Z (blue) → blue route
Y (yellow) → yellow route
X (red) → red route
RB (neon green) → green route
QB (black) → black route (if applicable)


Reference the player's color property when rendering the route
Additionally, implement these desktop features:
Primary Receiver Indicator:

If a route is marked as "Primary", show a small circle/dot at the end of the route (same as desktop)
This indicates the primary read for the QB

Motion Route Styling:

Pre-snap motion (behind line of scrimmage): dotted line
Post-snap route (after crossing LOS): solid line
The transition should occur at the line of scrimmage
Reference desktop implementation in PlayDesigner.tsx for exact styling

Issue 16: AI Overlay Too Large on Tablet
Problem: On iPad/tablet, the AI mode overlay takes over the entire screen. This is excessive — it should be a reasonably-sized modal, not a full-screen takeover.
Fix Required:

On tablet devices (screen width > 768px), make the AI overlay a centered modal instead of full-screen
Suggested dimensions for tablet: max-width of 600px, max-height of 400px
The modal should include:

"Describe Your Play" header
Text input area (doesn't need to be as tall on tablet)
Generate Play button + microphone button
Quick example chips
Close (X) button


On mobile phones (small screens), full-screen overlay is acceptable
The key point: it should NOT be transparent (Issue #6), but it also doesn't need to cover the entire screen on larger devices
Add a semi-transparent backdrop behind the modal that closes it when tapped
