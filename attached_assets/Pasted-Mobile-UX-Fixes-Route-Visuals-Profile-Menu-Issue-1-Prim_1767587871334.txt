Mobile UX Fixes - Route Visuals & Profile Menu
Issue 1: Primary Route Indicator Not Showing
Problem: When "Primary" is selected for a route, the small white circle with "1" inside should appear at the route endpoint (same as desktop). This indicator is not showing up on mobile.
Fix Required:

When a route has isPrimary: true, render a white circle with "1" at the endpoint
Reference the desktop implementation in PlayDesigner.tsx for exact styling

Implementation:
typescriptconst renderRoute = (route, ctx) => {
  // ... draw route line ...
  
  // If primary, draw indicator at endpoint
  if (route.isPrimary) {
    const endpoint = route.points[route.points.length - 1];
    
    // White circle
    ctx.beginPath();
    ctx.arc(endpoint.x, endpoint.y, 10, 0, Math.PI * 2);
    ctx.fillStyle = 'white';
    ctx.fill();
    ctx.strokeStyle = '#333';
    ctx.lineWidth = 1;
    ctx.stroke();
    
    // "1" text inside
    ctx.fillStyle = 'black';
    ctx.font = 'bold 10px Arial';
    ctx.textAlign = 'center';
    ctx.textBaseline = 'middle';
    ctx.fillText('1', endpoint.x, endpoint.y);
  }
};
Or if using SVG/React:
tsx{route.isPrimary && (
  <g transform={`translate(${endpoint.x}, ${endpoint.y})`}>
    <circle r="10" fill="white" stroke="#333" strokeWidth="1" />
    <text 
      textAnchor="middle" 
      dominantBaseline="middle" 
      fontSize="10" 
      fontWeight="bold" 
      fill="black"
    >
      1
    </text>
  </g>
)}

Issue 2: Player Menu State Not Resetting
Problem: When selecting a new player after drawing a route, the previous selections (Straight/Curved, Primary, Motion) carry over. Each new player should start with a fresh/default menu state.
Fix Required:

Reset all menu state when a new player is selected
The menu should always open with default values:

Route Type: none selected
Style: none selected (or default to Straight)
Motion: unchecked
Primary: unchecked



Implementation:
typescriptconst handlePlayerLongPress = (playerId: string) => {

  setSelectedRouteType(null);
  setSelectedStyle('straight'); // or null if you want no default
  setIsMotion(false);
  setIsPrimary(false);
  
  // Then open menu for this player
  setActivePlayerId(playerId);
  setShowPlayerMenu(true);
};
If using a menu component with local state:
tsxconst PlayerActionMenu = ({ player, onClose, onStartDrawing }) => {

Key: Make sure the menu state is tied to the specific player, not global state that persists between players.

Issue 4: Run Routes Should Be Black
Problem: Run routes are currently drawn in the player's color. They should always be black.
Fix Required:

When routeType === 'run', use black (#000000) for the route color regardless of player color

typescriptconst getRouteColor = (route, player) => {
  if (route.routeType === 'run') {
    return '#000000'; // Always black for run routes
  }
  
  if (route.routeType === 'block') {
    return '#FFFFFF'; // Always white for block routes
  }
  
  // For pass routes, use player color
  return player.color;
};
In rendering:
typescriptconst renderRoute = (route, player) => {
  const color = getRouteColor(route, player);
  
  ctx.strokeStyle = color;
  ctx.lineWidth = 3;
  // ... draw route path
};

typescriptconst renderBlockRoute = (route, ctx) => {
  ctx.strokeStyle = '#FFFFFF';
  ctx.lineWidth = 3;
  
  // Blocks are typically short, straight lines
  // May also have a perpendicular cap at the end to indicate "stopping"
  
  const start = route.points[0];
  const end = route.points[route.points.length - 1];
  
  ctx.beginPath();
  ctx.moveTo(start.x, start.y);
  ctx.lineTo(end.x, end.y);
  ctx.stroke();
